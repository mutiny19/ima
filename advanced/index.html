Indiana region settings

Three proposed structures for how Indiana MeshCore repeaters might tag regions, side by side so people can compare them. Each one starts from the same open base (us and us-in, unscoped traffic allowed, no default region) and differs only in how it names the places inside Indiana. Adding tags only lets more scoped traffic through, and companion users need none of this. Neighbouring groups publish their own plans: OKI Mesh, NEIMesh, MichMesh.

Proposals only. None of the three structures below has been decided, and none should be put on a repeater yet. They are here so Indiana Mesh can look at them together and pick, change, or drop them. The commands each one produces are for evaluation; until the community settles on one, a repeater should carry only the open base and whatever a neighbouring group publishes. Discuss on the Indiana Mesh Discord or open an issue.
Three proposed structures, none adopted. Simplest: an airport and a third of the state. Abbreviated: metro and region tags chosen on a map, with neighbours. County & district: the full builder, with county and IDHS district tags.

Simplest scoping

Two picks. Every repeater carries us and us-in; you add the airport code of the metro it serves, and which third of the state it sits in: us-in-north, us-in-central, or us-in-south. Four tags at most.

1 Airport

The lowercase code of the nearest metro's main airport. Skip it for a rural repeater away from every metro.

2 Where in the state

Pick one. One tag, by convention; no group publishes these yet.

3 Get the code


      

      
For evaluation; this structure is a proposal, not something to put on a repeater yet. If adopted, they would run on the repeater over USB serial or the app's remote admin, one line at a time, and then region list allowed should show * plus every tag. Near a state line, or for a repeater between two metros, switch to Abbreviated for neighbours and a second metro.

    

    

      
Method

      
    
        
  1. Base tags. us and us-in, with region allowf * and no default region, so unscoped traffic keeps flowing.
    2. 
        
  2. Airport. The same metro codes as the Abbreviated mode: published ones from OKI Mesh's region list and the observer services, the rest by the same convention.
    3. 
        
  3. Thirds. One tag each, us-in-north, us-in-central, us-in-south, following the us-in- form of the other Indiana tags. Their boundaries are the closest combination of Visit Indiana regions: North is Northwest, North Central, Northeast, and Wabash Valley; Central is West-Central, Central, and East Central; South is South Central, Southwest, Southeast, and South. Tags match by exact string, so a message scoped to us-in-north passes only repeaters carrying that tag; the Abbreviated mode's region tags (us-in-nw and so on) are different strings. No group publishes the thirds yet; carrying one is a proposal.
    4. 
        
  4. Commands and limits. As in the Abbreviated mode: the flat region def form on 1.16 and newer, region put per tag on 1.15 and openHop, plus region allowf on 1.14; 32 slots and 172 Discover Regions bytes, from the firmware source.
    5. 
      

    

  

  

    
Abbreviated scoping

    
The convention, in one sentence: every repeater carries us and its state as us-in, plus the lowercase three-letter airport code of each metro it serves. That's it. No default region, unscoped traffic allowed. The same three tags OKI Mesh, Waev, MeshMapper, and the observer firmwares already use for Indiana, so a guess lands on what your neighbours carry.

    

      
1 Where is it?

      

        

          
Two kinds of button on the map: click any county to add its region (tinted and numbered as on the Visit Indiana map), and click an airport-code pill to add that metro (shaded counties). Click again to remove. Pick one, or both.

          

        

        

          
Metro areas

          
Usually one. Two if you sit between them. None is fine for a rural repeater: it still carries us and us-in.

          

          

          
cvg and sdf are the OKI-published codes for the Indiana counties in the Cincinnati and Louisville metros.

          
Regions

          
If no metro fits, the region. The eleven regions of the state's own Visit Indiana map, the names most Hoosiers already use: us-in- plus the region's short code. No group publishes these yet; pick a region, a metro, or both.

          

          
Published codes appear in OKI Mesh's region list or an observer service's region list. By convention codes follow the same rule but no group has published them; using one is a proposal, and it only matters once a second repeater carries it.

        

      

    

    

      
2 Does it reach across the state line?

      
Most Indiana repeaters skip this step. Near a border, add the neighbouring group's own tags, spelled exactly as they publish them; each one only lets more scoped traffic through. oki, us-midwest, us-oh, and us-ky are published by OKI Mesh; mi and midwest by MichMesh; nei by NEIMesh. us-il and us-mi follow the state convention but no group publishes them yet.

Channel suggestions for what you picked

        
Scoping is for the rare message you want kept local. For everyday local chat, a channel does the job with nothing to configure on any repeater. Hashtag channels take their key from the name, so anyone who types the same name lands in the same room. Convention: # plus the place name, lowercase, letters only.

        

        
Tap to copy, then add it in the MeshCore app. People share channel names worth joining in #porchlight; these are only suggestions that follow the naming rule.

      Why these tags and not a hierarchy
      
    
        
  • Tags match by exact string.us-in does not imply us, and a nested tree is display only, so a hierarchy buys nothing on the air. What matters is that neighbours carry the identical string.
    • 
        
  • Invented strings split the mesh.A scoped message is dropped by the first repeater on its path that lacks the exact tag. Codes already published by neighbours and observer services are the ones most likely to be on that path.
    • 
        
  • Budget.A repeater holds 32 tags and answers Discover Regions in 172 bytes. Three short tags leave room for whatever comes next.
    • 
        
  • Scope limits what you send, never what you hear.Most people never scope. For local chat a channel like #hamilton or #eastcentral crosses every repeater with nothing to configure.
    • 
        
  • Why not "central" or "east central" tags.Those names have no agreed county boundaries and no neighbour carries them, so two people following the convention would still pick differently. The ten IDHS districts in the County & district mode are the defined version; the metro codes already cover the same ground.
    • 
      

    

    

      
Method

      
    
        
  1. Base tags. Every repeater carries us and us-in, with region allowf * and no default region, so unscoped traffic keeps flowing and nothing is held back.
    2. 
        
  2. Metro codes. The lowercase IATA code of the metro's main airport. Codes marked published are the ones in OKI Mesh's region list and the region lists of the observer services (Waev, MeshMapper, the Offband firmware). Codes marked by convention follow the same rule but no group has published them; listing one here is a proposal.
    3. 
        
  3. Which counties are in a metro. The counties of the metro statistical area, as the County & district builder already maps them for OKI's metros; cvg and sdf cover the Indiana counties OKI lists in the Cincinnati and Louisville metros. Counties outside every metro have no metro code; they are reached through their district.
    4. 
        
  4. Regions. The eleven regions of the Visit Indiana map, with each region's county list taken from its page there (October 2026). Tag form: us-in- plus the region's short code. Note that the County & district builder uses the ten IDHS districts instead, so a few region tags share a code with a district tag that covers a different set of counties (nw and cen are identical; nc, ne, wc, sc, se, sw differ at the edges). A repeater should follow one scheme or the other.
    5. 
        
  5. Neighbours' tags. Spelled exactly as each group publishes them (OKI Mesh, MichMesh, NEIMesh), never translated, because tags match by exact string.
    6. 
        
  6. Commands. The flat region def a|* b|* c form OKI's own examples use on firmware 1.16 and newer; one region put per tag on 1.15 and openHop; plus region allowf per tag on 1.14. Syntax from MeshCore's Region Management reference.
    7. 
        
  7. Limits shown. 32 region slots per repeater and a 172-byte Discover Regions reply, from the firmware source; the counter under the commands is tags and bytes against those caps.
    8. 
        
  8. Changing any of this. Codes, county lists, and districts live in one table in this page's source; propose a change by opening an issue, with the published source for the new value.
    9.

Shared tags

          

            
            
          

        

        
Tags that reach beyond your county and district. Phase 1 is the proposed starting set; add others only if your repeater should pass that group's scoped traffic. Tap Define for what each one means.

        

        

          
custom tag

          
A tag your group invents for a specific purpose, such as an emergency net, an event, or a club. It sits at the top level, beside the others. Every repeater that should pass that traffic has to carry the same exact spelling. Lowercase letters, digits, and hyphens, up to 30 characters.

          

          

        

      


      

        

          
Repeater CLI

          
        

        

        

        
For evaluation; this structure is a proposal, not something to put on a repeater yet. If adopted: send each step on its own, wait for the reply, then tick it off. Every step fits in one CLI message.

        
    
        
      
        
      
          Resulting region tree
          
      
        
      
        
      Steps must go in order: later steps refer to tags created earlier. If a step replies Err, fix it before moving on. region def does not clear old tags, so remove any you no longer want with region remove (children first), then run region to confirm each tag shows F.
      
      
      

      
      
        
      Companion app
      
        
      Indiana Mesh doesn't scope conversation: leave the default scope unset and channels unscoped, so messages reach everyone and keep working wherever you travel. Mute a busy channel instead of scoping it. If you run a bot or test pings you want kept local, this shows how. Every scope must be a tag the repeaters along the path carry, or the message stops at the first repeater that lacks it.

        Method
        
    
          
      
        1. Start from Phase 1. us, us-in, us-oh, us-ky, us-mi, us-il with unscoped traffic allowed and no default region. With nothing selected, the output is exactly that.
          2. 
      
        2. Districts. Indiana's ten homeland-security districts from the IDHS District Map, numbered 1 to 10, with short codes (nw, nc, ne, wc, cen, ec, w, sc, se, sw). Each county belongs to exactly one.
          3. 
      
        3. County codes. Three letters per county, chosen to be unique across Indiana; the lookup table is in this page's source. Indiana has no agreed statewide list yet, so these are this page's reference set.
          4. 
      
        4. Tag chains. us-in-<district>-<county> by default (the us-in-cen-mrn format, which keeps us-in as a real tag on the chain), or the in-us-cen-mrn alternative. Only the tags you tick are emitted; the tree shown is display only, since the firmware matches by exact string.
          5. 
      
        5. Shared tags. OKI Mesh's oki, us-midwest, us-southeast, and metro codes are offered as published; metro membership for out-of-state counties is approximated from metro statistical areas, and OKI's own maps govern.
          6. 
      
        6. Checks before display. Commands are run through a copy of MeshCore's region def and region put parsing; the 32-slot and 172-byte limits come from the firmware source; steps are sized to the CLI message length you choose.
          7. 
      
        7. Companion side. The companion panel only shows how a scope would be set; Indiana's starting point leaves companions unscoped. Any scope must be a tag the repeaters along the path carry.
          8. 
      
        8. Changing any of this. Districts, county codes, and shared tags live in tables in this page's source; propose a change by opening an issue, with the published source for the new value.
